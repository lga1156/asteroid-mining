# Инструкция ИИ: тесты Asteroid Mining

## Контекст

Монорепозиторий содержит React 19 + TypeScript + Vite в `frontend/` и Express 5 + TypeScript в `backend/`. Frontend использует Gravity UI, TanStack Query, Zustand и React Router. BFF интегрируется с Asteroids и Resources API.

## Выбор уровня

- Чистые преобразования, форматирование и validation — Vitest/Jest без DOM.
- React-поведение одного компонента — Testing Library; проверять роли, доступные имена и видимый текст.
- HTTP-контракт BFF — Supertest через экспортированный `app`; мокать только внешние сервисы/нестабильные часы.
- Цепочка frontend → BFF → upstream — Playwright с `e2e/mock-upstreams.cjs`; запрещено подменять ответ `/api` через `page.route` (допустимо только замедлить и продолжить реальный запрос для проверки loading).
- Геометрия и стили — `toHaveScreenshot` с фиксированным viewport; динамические области маскировать.

## Организация и имена

- Unit-файл размещать рядом с исходником как `Name.test.ts(x)`.
- API-тесты размещать в `backend/criteria-tests`.
- E2E разделять на `app.spec.ts` и `visual.spec.ts`, visual-тесты помечать `@visual`.
- Название теста описывает наблюдаемое поведение на русском языке.

## Фикстуры и изоляция

- React-данные брать из `frontend/src/test/fixtures.ts`.
- Для E2E использовать только фиксированные UUID v7 и ответы mock upstream.
- Очищать DOM автоматически и `localStorage` перед пользовательским сценарием.
- Не обращаться к публичным API и не зависеть от порядка тестов, текущего времени или случайных данных.
- Не проверять внутренние React state, классы CSS или порядок вызовов, если это не часть контракта.

Перед добавлением теста проверить, что сценарий не покрыт на более дешёвом уровне. После изменения запускать затронутый набор, затем build, lint и весь test suite.
